# R18 factory, dapp and backend rehearsal

**The local factory-born investment/withdrawal bridge is closed. Mainnet is unapproved; Noah remains V2.** Sushi is unactivated, Phoenix is retired for new routes only, and Curve remains deferred. No real wallet, key material, cryptographic signature, network transaction, physical deployment, production read/write, push or external sending is used in this revision.

## What is newly covered

The R17 contract proof created an actual routed Arka through the factory, but the earlier dapp/backend proof used a directly created fixture vault. R18 starts with only auxiliary contracts and the configured factory/registry. The child Arka and share token **do not exist** when the UI begins. The host rejects direct creation of either reserved child.

The new opt-in integration case `apps/web/tests/integration/factory-mainnet-vm.test.tsx` runs the real creation component, investment and manager controls, manual withdrawal UI, client review/execution adapter, Next connector GET handler and HTTP review/preparation backend. The backend uses its real `RpcCoordinator`, `VerifiedGateway`, `ReviewStore`, `ObservationIndex` checks and unsigned ABI operations. Each applied unsigned body and its exact SourceAccount authorization tree enters the isolated P29 host.

The sequence is:

1. Read the creator profile and fee, review the draft through the backend, and click creation. The actual `create_managed_routes` WASM creates Arka `CAHH3PQGGYGERAOTBUXCD4CBFB4PEKXZYFKO2VYSIDCSQ2J5YJ6VPFC7` and its share token. Both directional Sushi bindings and the non-denomination portfolio route are present. Exactly **5 USDC** is debited once, with no creation-fee approval action and no automatic deposit.
2. Connect the synthetic investor identity, authorize exactly **1000 XLM**, then explicitly deposit. The UI obtains the actual protected-share quote; the reviewed minimum and finite allowance are enforced. The allowance is consumed.
3. Switch to the synthetic manager, review the contract-generated investment quote and invest **100 XLM in USDC through Sushi**.
4. Return to the investor, separately authorize and deposit **three raw USDC units**. This retains the difficult residual case from the contract rehearsal.
5. Request all **10000000018 raw shares**, advance the local clock by 120 seconds, and review/execute **five balanced liquidation lots** calculated by the contract. There is no client sizing algorithm or automatic execution loop.
6. Review settlement. Simulate an index update delay, retain the receipt and resolve it by confirmation-only reads. Pause the venue through the synthetic governor, then collect the reserved withdrawal while paused.

The final payout is **999.4009043 XLM**. This is the entire redeemable value after the simulated exchange fees/spread, not guaranteed recovery of nominal principal. Network resource fee estimates are not deducted by this host-only ledger replay. Shares, NAV, pending/claimable/reserved rights, cancellations, and vault/router/adapter XLM and USDC balances end at zero; claimed value remains recorded. There are **14 unique applied financial actions**, including creation, with one test wallet response per action.

## Guards exercised across the layers

- Actual child instance/code, factory/registry, registry membership and registrar rows are read from the RAM state generated by WASM. The bridge no longer fabricates empty contract instances or an invented factory/registry list to admit the fund.
- The pre-submit recheck repeats the real backend preparation guards and compares the reviewed body, source, sequence, authorization and resources. Application approvals remain disabled outside the explicit test profile.
- The first liquidation's test wire reply is deliberately lost after applying it once. Reload retains public receipt metadata without XDR, blocks another operation, and offers confirmation-only recovery. No action is resent.
- Reusing the earlier liquidation plan after confirmation rejects without another financial operation. Each following lot requires a fresh contract plan and human-step review in the UI.
- Settlement remains pending while the synthetic catalog delivery is delayed. The UI blocks the next financial action until confirmation reconciliation. An already reserved cash claim still works while the venue is paused.
- Backend RPC methods remain read/simulate-only. The test wire belongs to the fixture driver, never to the backend; no signer, broadcaster, restore executor, keeper or second planner is added.

React components run in **jsdom**. The actual Next GET handler is invoked by the test fetch adapter; the backend is a real loopback HTTP service. Routing/WASM execute in the native P29 host against the unchanged, previously authorized frozen R8 Sushi snapshot at ledger **65206504**. Its 138 transitive locked packages retain the previously audited identity.

Funding, source account identities, oracle prices and governance are synthetic. Header freshness/sequence and complete index delivery are test metadata; getters and actual RAM rows supply financial balances and rights. The observation fixture is **not** the production indexer. Wallet approval is an invalid placeholder, the cryptographic verifier is mocked, and the local wire removes the placeholder before RAM execution. Receipt delivery is also a test double. **Zero real signatures or submitted chain transactions** result. Real Freighter/device, signer sets, public receipt cryptography, consensus, current target health/depth/admission and index completeness are not newly qualified. The earlier 58-case ephemeral cryptographic matrix is retained separately by source identity.
