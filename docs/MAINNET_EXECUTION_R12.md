# R12: client execution integration, validated locally

R12 connects the existing mainnet review backend to the dapp wallet and confirmation flow. Execution remains disabled: `mainnetApproved=false`, no deployed setting was changed, Noah stays V2, Sushi is unactivated and Curve is deferred. No production reads/writes, real signatures, chain submissions, pushes or deployments were performed.

## Changes

- `mainnetExecution.ts` adapts the existing managed transport. Preparing requires the frontend execution flag plus an approved backend profile, the public Stellar network, configured HTTPS RPC, an eligible managed fund and the reviewed wallet. Noah is rejected before profile/RPC access.
- The client verifies the exact envelope body/hash, fee, destination, amounts, action, source-account authorization and expiry. The future wallet response must contain one valid source signature on that same body; fee bumps, altered transactions and invalid responses are rejected. These guards were exercised with invalid placeholders and mocks, not real signing.
- `GET /recheck` reloads the unsigned review and repeats the existing complete preparation/simulation guards. Changed sequence, fee, resources, authorization, code/profile, plan or ledger drift blocks execution. It neither renews the reviewed envelope nor creates another archive. The backend still cannot sign or broadcast.
- The client consumes a prepared review before its single future RPC write. It persists public receipt metadata first, rechecks wallet/network/fund context and never automatically retries a write. Uncertain replies permit confirmation reads only, including after reload or disabling execution. A confirmed transaction remains pending until the verified catalog catches up.
- Investments, request/cancel/claim, manual liquidity lots, settlement and portfolio actions reuse the existing review/receipt UI. Creation uses the same flow and preserves the factory/target receipt; depositing remains a separate action. Late creation reviews are discarded when the public account or draft changes. The old local-network guard remains intact.

No contract, liquidation sizing rule, keeper, financial storage or router implementation changed. All 114 contract source files and all 24 selected WASM files are identical to R11/R9. The selected vault is still 130727 bytes, SHA-256 `3bd7b1dee46ca5db9e3e68789950df833b767dadf266a8aef7c054bf75202fa7`.
